# 工作流工具台

[![Build APK](https://github.com/cymylive/workflow-desk/actions/workflows/build-apk.yml/badge.svg)](https://github.com/cymylive/workflow-desk/actions/workflows/build-apk.yml)

一个用来**设计、跟踪、迭代你的工作流**的工具。电脑端是浏览器打开的本地软件，手机端是 Android APK。

比如你可以建一套「让生活幸福的工作流」，把每个环节写清楚，标注进度，
不断改进版本号 —— 让模糊的想法变成看得见、跑得动的流程。

---

## 快速开始（Windows）

1. 安装 [Node.js](https://nodejs.org)（如果还没装）
2. 双击 **start.bat**
3. 浏览器会自动打开 http://localhost:8317

就这样，没有别的步骤。

---

## 手机 / 平板访问（局域网）

服务默认监听 `0.0.0.0`，所以同一个 WiFi 下的手机可以直接用。

1. 电脑双击 `start.bat`，看黑色窗口里打印的「手机访问」地址，形如：

   ```
   手机访问 : http://192.168.66.252:8317
   ```

2. 手机浏览器输入这个地址即可。

> 手机连不上时优先检查：
> - 手机和电脑是否连同一个 WiFi
> - Windows 防火墙是否拦了 8317 端口
>   放行方法（管理员 PowerShell）：
>   ```
>   New-NetFirewallRule -DisplayName "工作流工具台" -Direction Inbound -LocalPort 8317 -Protocol TCP -Action Allow
>   ```

## 核心概念

### 工作流（Workflow）

一件**要达到某个目的**的事，拆成一条有序的链路。

| 字段 | 说明 |
| --- | --- |
| 名称 | 这套工作流叫什么 |
| 版本号 | 自己手动维护，比如 `1.0.0` → `1.1.0` |
| 目的与收益 | **为什么做这件事**，跑起来能得到什么 |
| 状态 | 开发中 / 已完成 / 已归档 |
| 标签 | 分类用，可搜索 |
| 置顶 | 置顶的工作流排在列表最上方，不受状态和更新时间影响 |
| 环节 | 按顺序要做的事 |

### 环节（Step）

工作流里的一步。

| 字段 | 说明 |
| --- | --- |
| 环节名称 | 比如「晨间启动」 |
| 这一步要做什么 | 具体动作、时长、完成标准 |
| 备注 / 说明 | 踩过的坑、执行要点、改进想法（黄色便签显示） |
| 状态 | 待开始 / 进行中 / 已完成 |

## 界面怎么用

### 左侧列表

- 点击切换工作流
- 顶部搜索框可以搜**名称、目的、版本号、标签、以及任意环节的文字**
- 列表按状态排序（开发中 → 已完成 → 已归档），同状态按最近更新排
- 每条显示状态徽章 + 迷你进度条 + `已完成/总数`
- **置顶**：鼠标悬停条目右上角出现 📍 按钮，点一下置顶；已置顶的显示 📌 并带金色左边条，再点取消
- 置顶的永远排在最前，其余按状态（开发中 → 已完成 → 已归档）再按最近更新排序

### 流程链路图

详情页顶部有一条横向链路，一眼看清整条工作流的先后顺序和进度：

```
① 晨间启动 ──→ ② 身体充电 ──→ ③ 深度工作块 ──→ ④ 关系连接
  ● 已完成      ● 进行中       ○ 待开始        ○ 待开始
```

- **节点配色**：绿=已完成，蓝=进行中（呼吸灯效果），灰=待开始
- **箭头**：前后两步都完成时，箭头变绿，直观看出「走到哪了」
- **点击节点**：下方对应卡片平滑滚动 + 高亮闪烁 1.3 秒
- **详细 / 紧凑**：右上角切换。紧凑模式只留序号和色点，环节多时一屏看完
- 环节多时横向滚动，不换行

### 右侧内容区

- **状态徽章**：点一下就在 开发中 → 已完成 → 已归档 之间轮换
- **环节状态徽章**：点一下在 待开始 → 进行中 → 已完成 之间轮换（已完成会自动加删除线）
- **拖动 ⠿ 手柄**：调整环节顺序
- **↑ ↓**：上移 / 下移环节
- **✎**：编辑环节
- **✕**：删除环节
- **编辑**：改工作流本身的名称、版本、目的、状态、标签
- **📌 置顶 / 📍 置顶**：头部左侧也能切换置顶，不用回侧栏
- **删除**：删除整个工作流（会二次确认）

### 快捷键

| 按键 | 作用 |
| --- | --- |
| `Ctrl + S` | 立刻保存 |
| `N` | 新建工作流；如果已经选中某个工作流，则新建环节 |
| `Esc` | 关闭弹窗 |

## 数据与备份

### 数据存在哪

```
工作流开发工具台/
├── data/workflows.json      ← 你的全部数据
└── backups/                 ← 自动快照（最近 50 份）
```

保存是**自动的**：你每改一下，400ms 后自动写盘，顶栏会显示「保存中… → 已保存」。

### 手动备份

点顶栏 **备份** 按钮：

- **导出**：下载一个 `workflow-backup-时间.json`，存到网盘 / U 盘
- **导入**：选择或拖入备份文件，覆盖当前数据（会二次确认）
- **自动备份列表**：每次写盘前自动留一份快照，可以一键回滚到任意历史版本

### 想彻底重置

删掉 `data/workflows.json`，重启服务即可。

## 技术说明

零第三方依赖，只用 Node.js 内置模块。

| 文件 | 作用 |
| --- | --- |
| `server.js` | HTTP 服务 + JSON 文件存储 + 自动备份 |
| `public/index.html` | 页面骨架 |
| `public/style.css` | 全部样式（含深色主题、移动端适配） |
| `public/app.js` | 前端逻辑，原生 JS，无框架 |
| `public/storage.js` | 数据层适配器（离线 localStorage / 连电脑 HTTP） |
| `smoke-test.js` | 后端接口冒烟测试 |
| `.github/workflows/build-apk.yml` | 自动编译 APK |

### 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 健康检查，返回局域网 IP |
| GET | `/api/state` | 读取全部数据 |
| PUT | `/api/state` | 覆盖保存全部数据 |
| GET | `/api/export` | 下载备份文件 |
| POST | `/api/import` | 导入备份 |
| GET | `/api/backups` | 列出自动备份 |
| POST | `/api/backups/restore` | 恢复某个备份 |
| POST | `/api/reset` | 清空数据 |

跑测试：

```bash
node smoke-test.js
```

## Android APK

电脑端和手机端**共用同一份前端代码**，通过数据层自动切换数据源。

### 安装

1. 打开仓库的 [Actions](../../actions) 页面
2. 点最新一次成功的 **Build APK**
3. 页面底部 **Artifacts** → 下载 `workflow-desk-apk`
4. 解压得到 `.apk`，传到手机安装（需允许「安装未知来源应用」）

> 打 tag（如 `v1.0.0`）时会自动创建 Release，直接在 Releases 页面下载更省事。

### 两种模式

| 模式 | 数据存哪 | 什么时候用 |
| --- | --- | --- |
| ⚪ **离线模式**（默认） | 手机本地 | 出门、没连电脑，独立使用 |
| 🟢 **连电脑** | 电脑上的 `data/workflows.json` | 在家，手机和电脑看到同一份数据 |

**切换方式**：点顶栏 **⚙ 设置** → 选模式。

- 选「离线模式」：打开即用，数据存手机
- 选「连电脑」：填入电脑地址（形如 `192.168.66.252:8317`，从 `start.bat` 窗口里抄），点「测试连接」通过后保存

顶栏左侧的徽章会显示当前状态（🟢 已连接 / ⚪ 离线模式），点它也能打开设置。

### 数据安全

- **离线模式**：每次保存前自动留 1 份快照，保留最近 **10 份**（localStorage 空间有限）
- **连电脑模式**：使用电脑端的自动备份，保留最近 **50 份**
- 两种模式都能在「备份」面板里**导出 JSON** 存到网盘或电脑
- 换手机 / 重装 APP 前，务必先导出备份

### 电脑端浏览器行为

用浏览器打开 `http://localhost:8317` 时，会自动连本机服务器（不需要任何配置），行为和以前完全一致。

### 自己编译

不用在本地装 Android SDK —— 推送到 GitHub 后由 Actions 自动编译：

```bash
git add -A
git commit -m "你的改动"
git push
```

想直接出 Release 包就打 tag：

```bash
git tag v1.0.1
git push origin v1.0.1
```

本地跑 Capacitor 命令（可选，用于调试）：

```bash
npm install
npx cap sync android     # 把 public/ 同步进 android 工程
```
